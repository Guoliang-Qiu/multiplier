# 新发现的 Pareto 候选

此目录保存经过验证的候选快照，以及明确标记的公平比较基线。

- 优化目标：加权门成本与 `evm_db`，两者均越小越好。
- 基线和新候选使用同一套综合流程及预算后再比较。基线快照不算新发现；被支配的历史候选保留来源记录并明确标记。
- 每个候选必须通过原版 `eval.py` 的完整默认评估，以及 `gate_cost.py` 的成本评估。
- 保存固定配置的电路实现及同名 JSON 评估记录，记录来源、完整指标和评估配置；候选入口为零参数 `build_circuit()`。
- 搜索和修改在 `generations/` 中进行，此处保存验证后的候选快照。

## 公平重综合后的已验证点

| 电路 | 加权成本 | 完整 EVM (dB) | 身份 |
|---|---:|---:|---|
| `candidate_pareto_961.py` | 961 | -57.61590546455796 | 原999成本电路的等价重综合基线 |
| `candidate_pareto_969.py` | 969 | -57.64234373351301 | 原1005成本电路的等价重综合基线 |
| `candidate_pareto_973.py` | 973 | -57.70845642064542 | 新的非支配精度/成本折中点 |
| `candidate_pareto_975.py` | 975 | -57.74524478907551 | 新的非支配精度/成本折中点 |

全部10个初始电路与两个新候选都使用同一ABC版本、AIG转换、脚本顺序、
最多两轮预算和严格降成本接受规则，且重跑原版 `eval.py` 的1,050,624例。
已导出文件与被评估的 `generations/9/` 快照逐节点相同；JSON记录完整指标、
哈希、等价证明和比较协议。

973和975的精度优于961，但成本较高，因此仍是Pareto点，**没有同时击败基线**。
当前公平严格目标是成本 **<961** 且 EVM **<-57.61590546455796**，尚未达到。
后续更换综合流程或预算时，必须同步重跑基线。

`candidate_pareto_1009.py` 和 `candidate_pareto_1011.py` 是未重综合的历史来源，
分别被973和975版本支配；不是当前前沿点。
